# Безопасность

## Что нельзя прикладывать к issue

- `desktop.log`, `fr_drv_ng.log` и другие журналы кассы целиком;
- `vk-token.dat` и значения `BIFIT_REPORT_VK_TOKEN`;
- каталог `C:\ProgramData\BifitReport`;
- банковские слипы, номера карт, телефоны, e-mail, ИНН и идентификаторы устройств.

Для диагностики достаточно версии приложения, обезличенного фрагмента `status.json`, кода ошибки доставки и времени события.

## Модель доступа

Агенту нужен только доступ на чтение к журналу БИФИТ и запись в собственный каталог состояния. Он не должен получать права на изменение каталога данных кассы и не должен открывать `data.mv.db`.

Токен VK шифруется Windows DPAPI в области `LocalMachine`. Защита дополняется ACL каталога: чтение разрешается только `SYSTEM`, локальным администраторам и пользователю, который сохранил токен.

## Архив журналов

При `Archive:Enabled = true` агент копирует ротированные журналы в отдельный каталог, чтобы они пережили очистку, которую выполняет БИФИТ. Архив содержит **исходные строки журнала** (служебные параметры, идентификаторы устройств, данные документов), поэтому:

- каталог архива должен быть закрыт ACL, отдельным томом или защищённым сетевым ресурсом;
- не размещайте архив в git, облачных синхронизациях и общедоступных папках;
- для длительного хранения используйте шифрование тома (BitLocker) и резервное копирование;
- архив не отправляется в VK: агент только копирует файлы и ничего из них не публикует.

## Веб-просмотр журналов

`BifitReport.LogViewer` использует ASP.NET Core Identity с локальной SQLite-базой. Пароли хранятся только как хеши, cookie имеет `HttpOnly`/`SameSite=Strict`, ключи шифруются Windows DPAPI, после пяти неудачных входов учётная запись блокируется на 15 минут. Для удалённого доступа обязателен HTTPS с доверенным сертификатом; HTTP разрешён только на loopback.

По умолчанию сервис маскирует токены, контактные данные, номера карт и длинные идентификаторы. `LogViewer:AllowRawLogs=true` отключает это ограничение по запросу пользователя интерфейса и должен применяться только в изолированной сети с узким набором учётных записей. Открытие каждого файла, включая raw-режим, записывается в аудит без поисковых строк и содержимого журнала.

Не выдавайте учётной записи службы права на изменение каталогов БИФИТ. Не добавляйте в `Sources` пользовательские каталоги или ресурсы, в которых недоверенные пользователи могут создавать reparse points. Сервис отклоняет symlink/junction внутри корня, но allow-list каталогов остаётся основной границей доступа.
